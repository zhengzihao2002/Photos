# Decisions

One line each, newest area last.

- **One branch, merges to main.** Work happened on `claude/busy-cerf-m4gtyu` and was merged into `main` at milestones (the owner asked for direct merges).
- **CI is the Mac test bench.** The build environment was Linux; everything that needs macOS (the app itself, `sips`, `hdiutil`, `codesign`) runs on a `macos-14` GitHub runner. The GeoNames download is blocked in the Linux sandbox, so the landmark dataset is built by a manual CI job (`ci.yml`, input `build_landmarks`) that commits `resources/geo/landmarks.json`.
- **M13 landmarks.** GeoNames feature codes with per-code match radii; notability = English Wikipedia link, or names in ≥ 6 languages (airports, churches, museums… need the link). Nearest landmark whose own radius contains the point wins; ties within 50 m go to notability, then smaller radius. National parks get a 20 km radius by name because GeoNames stores a single centre point. City names stay in `place_locality_*`; the landmark has its own columns (migration 17). Dataset version is `places*100 + landmarks` so either change recomputes rows once. A user title always wins over a landmark.
- **M14 language.** Catalog keys with whole-sentence values and CLDR plurals; locale stored in `config.json`; the main process owns it and tells every window; **a language change reloads the pages** (simplest way to guarantee nothing keeps a stale string). Menus use explicit labels, not Electron roles. A Traditional-Chinese Mac gets Simplified, not English. Date ranges are whole catalog sentences, not `Intl.formatRange` (its Chinese output differs between ICU versions). Pseudo-locale: `PHOTOS_PSEUDO_LOCALE=1`.
- **Errors keep English details.** Notices are localized sentences; the technical text after the colon (an OS error message) stays as the system gave it.
- **M8d scale.** Synthetic database benchmark instead of 100,000 real files (CI cannot hold them); bulk keyword edits switched to set statements above 500 items; FTS5 not added because `LIKE` search meets the target.
- **M11 write guard** wraps Node `fs` in every thread and denies anything outside the data/temp folders or inside a source folder; external tools only through `safe-exec.js` with an allowlist; page scripts never get file paths (`photos-media://thumb|crop|item`), and `file:` is gone from the CSP image/media sources.
- **M9.** arm64 only, `asar` **off** (worker threads, native modules and bundled tools then load from plain files, which removes a whole class of packaging problems; the app is open source anyway), ad-hoc signature applied in an `afterPack` hook, release ZIP made with `ditto`. App id `io.github.zhengzihao2002.photos-clone`. Icon: original artwork (`resources/icon/icon.svg`), `.icns` written directly by `tools/build-icon.js` (no `iconutil` needed).
- **M15 Live Photo pairing.** Pairing is by Content Identifier (still: Apple MakerNote tag 0x0011 read from the first 512 KB; video: container tag `com.apple.quicktime.content.identifier`), within one source, across folders. `live-pairing-pass.js` runs after reconcile in full and scoped scans and is the only writer of the three live columns; the batch-time name matcher no longer writes them. Ambiguity (copies, 2 stills + 2 videos) resolves by same stem, then the only pair in a folder, then mutually nearest capture time within 3 s; ties stay unpaired and visible. Name-stem fallback applies only when neither file has an identifier, same folder, video of 5 s or less (a first guess, never exercised on real data). Migration 18 adds `content_identifier`, `live_pairing_version` and two partial indexes. The one-time backfill never touches `file_mtime`, `file_size_bytes`, `extraction_version` or `updated_at`. Hidden videos keep their thumbnails and face rows.
- **M15.9 Info buttons.** A Live Photo's Info shows Show Photo in Finder and Show Video in Finder; other items keep one button.
